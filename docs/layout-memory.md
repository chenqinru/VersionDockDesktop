# 布局记忆

项目窗口记住正常尺寸、位置和最大化状态；不恢复最小化或全屏状态。首次打开时按显示器工作区域计算默认尺寸。保存使用应用配置目录下的 `window-layout.json`，与工作台设置分开，避免欢迎页或临时拖动窗口覆盖项目尺寸。

- 同一运行期间，每个业务窗口分别保存自己的项目尺寸；返回欢迎页再进入项目时恢复该窗口的记录。
- 重启或打开新窗口时，以上一次实际调整过的项目窗口作为起始布局。新窗口独立调整，标签拖出时保留源窗口尺寸和鼠标落点。
- 欢迎页保持 880 × 540；空间不足时限制到显示器可用区域。欢迎页的位置在当前窗口会话内保留，不覆盖项目记录。
- 恢复时识别显示器工作区域，校正不可见位置、过大尺寸及不同缩放比例。最大化时单独保留正常尺寸，取消最大化后不会变成屏幕大小。
- 原生移动和缩放事件防抖 250ms；关闭窗口和退出应用时立即补存。

欢迎页和项目页切换时直接显示目标页面，标题栏与内容同时切换；内容区持续参与响应式布局，不使用整页加载遮罩，也不等待原生尺寸确认后再展示。发起尺寸请求前，通过两次 `requestAnimationFrame` 给目标页面一次绘制机会；120ms 兜底，隐藏时不等待，快速反向切换或卸载时取消尚未发出的请求。标签转移继续立即显示并保留原生尺寸。仓库扫描、历史和分支读取保留各自的局部加载反馈，与窗口切换分开。

原生端仍持续核对窗口与 WebView 的真实边界，不匹配时按当前客户区修复，目标尺寸、最大化状态及 WebView 边界连续两次确认后返回实测逻辑尺寸。此确认只用于原生几何同步和布局记忆，不遮挡页面，1200ms 超时兜底，最小化时跳过。Windows 同时核对 WebView2 控制器及其承载窗口，避免控制器尺寸正确但承载窗口仍停留在欢迎页大小。启动、新建窗口、窗口缩放、DPI 变化及重新聚焦时也检查边界，只有铺满客户区后才启用 1:1 自动缩放。修复始终在原生主线程读取最新尺寸，不复用延迟事件中的旧值。尺寸请求沿用 Bridge 串行队列，尺寸切换的中间态不写入用户窗口记录；旧请求返回不能改变当前页面。尺寸与布局确认不等同于操作系统合成器已经完成呈现，残影仍需三平台原生窗口验收。

macOS 在已显示的欢迎页与普通项目尺寸之间切换时，以一次 AppKit `setFrame:display:animate:` 同时更新位置和大小，复用下述原生缩放绘制同步。原生调用在主线程执行，不持有布局或 WebView 锁。首次布局、隐藏或最小化窗口，以及系统启用“减少动态效果”时直接设置尺寸。退出全屏、恢复最大化状态仍使用 Tauri 的原生状态流程，保留取消最大化后的正常尺寸；Windows 和 Linux 继续使用各自的窗口管理流程，不通过前端定时器逐步设置窗口尺寸。

macOS 主 WebView 单独使用 AppKit：保持父视图对子视图的自动布局以及 WebView 的宽高自动伸缩，边界异常时直接将其 `frame` 修正到父视图的 `bounds`，并使用 `DuringViewResize` 重绘策略。原生缩放回调直接执行检查，不再每次创建后台任务后转回主线程；稳定边界轮询也走同一修复方法。以上 Tauri 1:1 比例缩放仅用于 Windows 和 Linux，macOS 不启用：Wry 的 macOS `set_bounds` 仅能调整子 WebView，对主 WebView 无效。

仅有正确的原生边界仍可能出现留白：WebKit 内容进程可以晚一帧才按新视口绘制。可见窗口的拖动缩放，以及双击标题栏最大化、还原，直接在 AppKit `NSWindowDidResizeNotification` 中通过公开的 `callAsyncJavaScript` 等待两次 `requestAnimationFrame`，在两个回调之间完成一帧绘制，再结束当前原生缩放回调。等待期间服务原生事件循环，不使用睡眠、截图拉伸、额外遮罩或 WebKit 私有 API。单次等待预算为 120ms，渲染无响应时本轮缩放跳过后续等待，下一轮重新尝试；每个窗口单独防重入，销毁时取消。仅在 AppKit 的 `inLiveResize` 阶段处理，避免普通尺寸设置中重入 Tauri 的 WebView 锁。该公开 WebKit API 需要 macOS 11+；旧系统保留原有边界修正。

Tao 0.35.3 的最大化实现原本在 AppKit 动画期间持有窗口状态锁，而动画自身会运行嵌套事件循环。因此同时保留同版本源码的[最小补丁](../src-tauri/vendor/tao/PATCHES.md)，在更新状态、读取恢复尺寸后先释放锁，再进入两处分支的原生窗口动画。否则绘制同步中处理窗口状态查询会死锁。后续升级 Tao 时应核对两处锁范围；上游修复后可移除本地覆盖。

绘制同步会让窗口事件在动画中途得到处理。原生缩放开始前先记录当前尺寸；等待绘制时跳过布局记忆，沿用原有防抖在结束后保存最终状态，避免把动画中间值当成正常窗口尺寸。刚拖动完立即双击最大化时，也保留刚调整的尺寸。

历史列表在视口暂未测量时只渲染可见范围附近的提交，避免窗口切换期间回退成全量 DOM；缩放宽度只在引用标签显示数量变化时更新 React 状态。标题栏的窗口尺寸上报在停止缩放 100ms 后合并发送，原有 800ms 周期保留。原生绘制同步应使用 NIC 等真实多仓库工作区验证，并覆盖拖动缩放、双击标题栏最大化与还原、重启恢复及全屏退出；连续记录中间帧，检查右侧、底部和标题栏，不以最终尺寸正确代替过程验收。内容进程挂起或超出等待上限时允许降级，不能保证任意负载下完全没有呈现延迟。

macOS 标题栏通过当前窗口的 AppKit 全屏通知控制红黄绿按钮预留空间：进入动画完成后收起，退出动画开始时恢复。通知中直接通过 WKWebView 公共接口更新文档上的原生全屏外观标记，避免 Tauri 用户事件队列在动画期间延迟；正常事件通道随后同步 React 状态，过期的查询不能覆盖原生通知。外观标记由原生端单独维护，不直接改写 React 拥有的 DOM 属性。监听按窗口注册，销毁时移除；WebView 使用弱引用。需同时验收动画期间与结束后的标签位置。

工作台分割线按应用全局保存：提交面板、分支栏、详情栏宽度，以及详情信息区高度、分支比较上下区域比例。继续沿用 `state.json` 中的 `layout`。分支比较使用比例，详情高度按当前容器限制；窗口缩小时不覆盖用户保存的首选值。提交消息输入区和输出面板高度继续沿用已有本地存储。

拖动更新防抖 180ms，松开鼠标时立即提交。布局写入串行执行，后端只合并本次改变的字段，窗口间同步几何调整；不会因为另一窗口调整布局而切换当前窗口的操作标签。失败时保留错误提示并恢复已确认状态。

“设置 → 外观 → 界面 → 工作台布局 → 重置布局”恢复所有面板尺寸和当前窗口的默认布局，并清除旧窗口记录。其他已打开窗口保留当前原生位置，面板尺寸同步重置。该操作保留主题、字号、语言、文件视图、工作区及仓库设置，也支持设置搜索。

验证应区分 Rust 存储与边界测试、浏览器渲染，以及原生窗口验收。显示器拔插、Windows 和 Linux 的原生窗口管理仍需分别验收。
