# 布局记忆

项目窗口记住正常尺寸、位置和最大化状态；不恢复最小化或全屏状态。首次打开时按显示器工作区域计算默认尺寸。保存使用应用配置目录下的 `window-layout.json`，与工作台设置分开，避免欢迎页或临时拖动窗口覆盖项目尺寸。

- 同一运行期间，每个业务窗口分别保存自己的项目尺寸；返回欢迎页再进入项目时恢复该窗口的记录。
- 重启或打开新窗口时，以上一次实际调整过的项目窗口作为起始布局。新窗口独立调整，标签拖出时保留源窗口尺寸和鼠标落点。
- 欢迎页保持 880 × 540；空间不足时限制到显示器可用区域。欢迎页的位置在当前窗口会话内保留，不覆盖项目记录。
- 恢复时识别显示器工作区域，校正不可见位置、过大尺寸及不同缩放比例。最大化时单独保留正常尺寸，取消最大化后不会变成屏幕大小。
- 原生移动和缩放事件防抖 250ms；关闭窗口和退出应用时立即补存。

欢迎页和项目页切换时保留标题栏，仅遮盖内容区。原生端持续核对窗口与 WebView 的真实边界，不匹配时按当前客户区修复，目标尺寸、最大化状态及 WebView 边界连续两次确认后返回实测逻辑尺寸；前端确认视口与文档布局匹配，连续两帧保持一致后展示内容。Windows 同时核对 WebView2 控制器及其承载窗口，避免控制器尺寸正确但承载窗口仍停留在欢迎页大小。启动、新建窗口、窗口缩放、DPI 变化及重新聚焦时也检查边界，只有铺满客户区后才启用 1:1 自动缩放。修复始终在原生主线程读取最新尺寸，不复用延迟事件中的旧值。两端分别以 1200ms 超时兜底，最小化或隐藏时跳过等待，异常时解除遮罩。尺寸切换的中间态不写入用户窗口记录；快速切换时旧请求不能解除新请求的遮罩。尺寸与布局确认不等同于操作系统合成器已经完成呈现，残影仍需三平台原生窗口验收。

macOS 主 WebView 单独使用 AppKit：保持父视图对子视图的自动布局以及 WebView 的宽高自动伸缩，边界异常时直接将其 `frame` 修正到父视图的 `bounds`，并使用 `DuringViewResize` 重绘策略。原生缩放回调直接执行检查，不再每次创建后台任务后转回主线程；稳定边界轮询也走同一修复方法。以上 Tauri 1:1 比例缩放仅用于 Windows 和 Linux，macOS 不启用：Wry 的 macOS `set_bounds` 仅能调整子 WebView，对主 WebView 无效。此处理减少视图尺寸滞后和旧内容保留，不保证 WebKit 内容进程或系统合成器在负载下永远没有短暂呈现延迟。

历史列表在视口暂未测量时只渲染可见范围附近的提交，避免窗口切换期间回退成全量 DOM；缩放宽度只在引用标签显示数量变化时更新 React 状态。标题栏的窗口尺寸上报在停止缩放 100ms 后合并发送，原有 800ms 周期保留。NIC 多仓库工作区的连续帧检查仍能复现快速放大时的边缘空白，不能将这些改动或最终尺寸正确当作留白已消除的证据。

macOS 标题栏通过当前窗口的 AppKit 全屏通知控制红黄绿按钮预留空间：进入动画完成后收起，退出动画开始时恢复。通知中直接通过 WKWebView 公共接口更新文档上的原生全屏外观标记，避免 Tauri 用户事件队列在动画期间延迟；正常事件通道随后同步 React 状态，过期的查询不能覆盖原生通知。外观标记由原生端单独维护，不直接改写 React 拥有的 DOM 属性。监听按窗口注册，销毁时移除；WebView 使用弱引用。需同时验收动画期间与结束后的标签位置。

工作台分割线按应用全局保存：提交面板、分支栏、详情栏宽度，以及详情信息区高度、分支比较上下区域比例。继续沿用 `state.json` 中的 `layout`。分支比较使用比例，详情高度按当前容器限制；窗口缩小时不覆盖用户保存的首选值。提交消息输入区和输出面板高度继续沿用已有本地存储。

拖动更新防抖 180ms，松开鼠标时立即提交。布局写入串行执行，后端只合并本次改变的字段，窗口间同步几何调整；不会因为另一窗口调整布局而切换当前窗口的操作标签。失败时保留错误提示并恢复已确认状态。

“设置 → 外观 → 界面 → 工作台布局 → 重置布局”恢复所有面板尺寸和当前窗口的默认布局，并清除旧窗口记录。其他已打开窗口保留当前原生位置，面板尺寸同步重置。该操作保留主题、字号、语言、文件视图、工作区及仓库设置，也支持设置搜索。

验证应区分 Rust 存储与边界测试、浏览器渲染，以及原生窗口验收。显示器拔插、Windows 和 Linux 的原生窗口管理仍需分别验收。
