# AI 与 VersionDock 插件对照检查

检查日期：2026-10-08。参考插件提交 `790939e`，Desktop 基线 `7a8325a`（0.1.9）及本次工作区修复。插件仅作为只读参考，Desktop 仍通过独立 Rust／Tauri 实现。

## 检查结论

Desktop 已贯通提交信息、提交解释、代码审查、智能拆分及冲突解决五类任务，但不能称为与插件完全一致。本次修复确认的协议、预算、CLI 结果和异步状态问题；下面列出保留差异及验收边界。

## 本次修复

| 链路 | 原有差异或问题 | 修复及验证 |
| --- | --- | --- |
| Responses 请求 | `input` 使用字符串，未发送 SSE Accept 请求头 | 与插件一致地发送 `user` 消息数组、`input_text`、`max_output_tokens`、`stream: true` 和 `store: false`；本地代理严格校验请求格式 |
| Chat Completions 请求 | 按模型名前缀猜测 Token 参数；模型别名可能选错 | 按插件的 Provider 规则选择：OpenAI 使用 `max_completion_tokens`，自定义及 Gemini 使用 `max_tokens`；OpenAI 请求 usage 流数据 |
| 流式完成 | 完成事件后仍等待 EOF；`error: null` 被误判 | 完成事件结束读取；空错误不拒绝请求；Chat／Claude 的 finish reason 仍保留 EOF 校验，不提前丢弃后续事件 |
| 响应兼容 | 漏读最终文本及内容数组；过度依赖 Content-Type | 支持最终文本、Chat 内容数组、完整消息回退及实际正文格式识别；容忍非 JSON 保活事件，同时保留无完成事件的中断检查 |
| Responses 状态 | 嵌套失败／截断状态未检查 | 检查 `response.error`、`response.status` 和 `incomplete_details`；拒绝将失败或截断的正文作为成功结果 |
| 错误诊断 | 界面只有统一提示，服务端错误正文被丢弃 | 保留状态码及服务端错误摘要；已知密钥及常见凭据模式先脱敏，再限制长度；错误正文读取有大小上限并支持取消 |
| Token 预算 | ASCII／中文估算、解释／审查／拆分输出预算与插件不同 | 复用 Rust 的统一预算模块，按插件公式估算文本和主要任务输出；冲突预算保留 Desktop 对完整三方证据的保守估计，最低输出空间提高到 8192，且受用户上限约束 |
| 拆分截断 | 缺少插件的一次扩大输出预算重试 | 仅对拆分的 API 输出预算耗尽重试一次；不超过配置上限，不对权限错误或内容过滤重试，不发布半成品拆分结果 |
| JSON 修复 | 修复请求直接使用配置的全部输出上限 | 按修复内容估算预算，受配置上限约束；继续保留结构及覆盖校验 |
| Codex CLI | 多段 `agent_message` 的累计结果被最后一段覆盖；能力检测漏检实际使用的参数 | 保留完整累计结果，能力检测补齐 `--cd`／`--skip-git-repo-check`；使用临时 CLI 脚本验证四种适配器和取消行为 |
| 提交信息异步结果 | 同一工作区内切换仓库或所选文件时，旧任务仍可能写入输入框 | 选择范围变化时取消任务，流及完成回写检查当前范围；验证新草稿不被旧结果或旧草稿覆盖 |
| AI 诊断日志 | AI 链路没有接入应用日志，无法查看请求参数概要、重试或失败阶段 | 接入现有输出面板及磁盘日志，新增 AI 通道；关联工作区、操作和 AI 请求编号，记录阶段、Provider／协议／模型、预算、HTTP 状态、耗时、首段延迟、输出统计和服务端 Token usage，覆盖取消、重试、JSON 修复及 CLI 状态 |

实现位置：`src-tauri/src/ai/transport.rs`、`budget.rs`、`mod.rs`、`agent_cli.rs`、`src/components/AiCommitActions.tsx`。

AI 日志入口：打开应用的“输出与日志”，在通道筛选中选择“AI”，展开“详情”查看诊断数据；可用原有复制、导出及打开日志目录操作保存记录。模型输入、Diff、提示词及生成正文不主动记录；API 地址移除查询参数、片段及嵌入凭据，服务端错误中的已知密钥及常见敏感字段在写入前脱敏。每段文本不会单独输出日志，避免流式请求刷屏。

## 已核对的共同约束

- 五类任务均通过 Bridge 到达 Rust；API 和四种 CLI 适配器已有真实实现。
- 工作区提示词文件名和“工作区 → 全局 → 内置”优先级对应；两端的全局存储位置独立。
- 审查只使用真实 Diff 锚点，定位前重新验证 Diff；冲突输出要求完整、唯一的索引覆盖和无冲突标记，应用前检查文件指纹。
- 拆分要求每个变更单元被覆盖一次，应用保留后端写锁、状态指纹及提交树一致性校验。已有真实临时 Git／SVN 测试覆盖应用、未选择的改动保留、历史重组及外部 index.lock。
- 工作区切换、取消和重新请求保留请求身份检查；新增提交选择范围保护。

## 保留差异

| 项目 | 当前状态及影响 |
| --- | --- |
| GitHub Copilot | 插件通过 VS Code Language Model API 接入；Desktop 无对应 Provider。不能把这部分算作已经迁移 |
| 全局配置及密钥 | 插件配置来自 VS Code，Desktop 来自自身设置及系统安全存储；需要在 Desktop 保存密钥，全局提示词不自动共享 |
| HTTP 跳转 | 插件的 fetch 默认跟随跳转；Desktop 拒绝跳转。需要最终 API 地址，不能将收到 3xx 自动解释为模型不支持 |
| temperature | 插件普通 API 任务默认 0.2、代码审查为 0；Desktop 当前未发送该参数。未盲目添加，因为部分模型拒绝该参数。结果措辞与稳定性不能保证相同 |
| 大上下文分配 | 插件先放所有文件摘要，再轮流分配 Diff 块；Desktop 按文件分配预算，审查还保留同文件未改变引用。超大、多文件任务的可见证据不完全相同，需查看截断提示 |
| 多仓库 CLI 工作目录 | 插件使用共同祖先目录，并确认扩大范围；Desktop 使用第一个证据仓库作为工作目录，提供全部上下文并禁止模型主动执行操作。读取范围与会话复用方式不同 |
| Antigravity 权限拒绝恢复 | 插件可在首次工具权限拒绝后发送一次“仅依据现有证据回答”的恢复消息；Desktop 当前未实现此恢复分支。仍可能出现插件成功、Desktop 返回无正文的情况 |
| 截断结果策略 | Desktop 拒绝截断结果；插件的部分文字任务可能保留部分输出。保留 Desktop 的完整性要求，不将半个提交信息或结构结果当作成功 |

## 验证和验收边界

本次执行前端完整检查和 Rust 完整检查。测试包含本地 HTTP 代理、四类临时 CLI 脚本及真实临时 Git／SVN 仓库；不会向用户工作仓库执行破坏性验收。

同事的配置“自定义／Responses／`https://apiproxy.uraga.top/v1`／`gpt-5.6-luna`”会请求 `/v1/responses`；本地请求测试使用相同 Provider、协议及模型名。未取得或使用同事的密钥，未连接该代理做认证请求，也未完成各真实 CLI 账号及 Tauri 界面验收。源码检查和本地测试不能替代这些验证；修改需要重新构建 Desktop 后生效。
