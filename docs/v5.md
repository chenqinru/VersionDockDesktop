# VersionDock Desktop V5 后续功能需求

## 1. 文档目标

V5 以当前 VersionDock Desktop 源码和 `docs/versiondock-feature-comparison.md` 为基线，继续补齐 VersionDock 插件已经具备、且适合独立 Desktop 产品的非 AI 功能。

本轮已重新核对两个仓库：

- 可写工程：`/Users/chenqinru/Project/VersionDockDesktop`
- 只读参考：`/Users/chenqinru/Project/VersionDock`

V5 只处理能在当前源码中确认的缺口，不重复实现 V4/V4-2 已经完成的并发、取消、Watcher、Capability、安全存储、多窗口、Diff 和批量结果能力，也不照搬 VS Code Extension Host 概念。

## 2. 明确不做

V5 不实现：

- 任何 AI 功能、AI 设置、Provider、Prompt、API Key 或 AI 网络请求。
- Git/SVN Ghost Text。
- Git/SVN Blame，以及依赖 Blame 的 Line History 和编辑器行标注。
- VS Code Native Changes、SCM Resource、Activity Bar、Command Palette、Editor Tab Undock 等宿主专属能力。
- 独立 Submodule 标签、面板或新的 Submodule 管理中心。
- 为模仿 VS Code 而新增的多根 Workspace、Explorer 或 Editor API 抽象。
- 只有 UI、Mock 数据或没有真实 Backend 调用方的占位功能。
- 与 V5 功能无关的视觉系统重做。

在线头像、GitHub/GitLab Provider 属于普通网络能力，不属于 AI；但必须遵守本文件的隐私、安全存储和显式授权边界。

## 3. 当前完成基线

- Git/SVN Status、Stage、Unstage、Rollback、Delete、Ignore。
- Commit、Commit & Push、Amend、多仓库批量提交和部分成功恢复。
- Stash、Shelf、Changelist、Unpushed Commit 操作。
- Git/SVN History、Commit Detail、Merge Commit、聚合 Changes 和 File History。
- Branch、Tag、Remote、Identity、Worktree、Subtree、Submodule 和 Conflict 工作流。
- Diff 类型矩阵、二进制和大文件状态、Project Colors。
- 多工作区、多窗口标签移动、应用内通知、更新器和诊断报告。
- OperationEvent、请求取消、进程树终止、仓库锁、读写并发限制和精确 Watcher Scope。
- Runtime Capability、通知权限和 SVN 系统安全存储。
- V4-2 File History 分页取消、局部 busy、Submodule 菜单目标和启动栈溢出修复。

2026-08-30 自动化基线：

- 前端 26 个测试文件、175 项测试通过。

- Bindings、TypeScript、ESLint、可见文本扫描、Vite、Rust fmt、Clippy 均通过。
- 默认 Tokio worker 栈下的真实 Tauri 开发启动通过。

## 4. P0：本地核心功能闭环

### 4.1 Initialize Git Repository

当前欢迎页或空工作区只能提示未发现仓库，没有初始化入口。

V5 需要：

- 当已打开目录中不存在 Git/SVN 仓库时显示 Initialize Repository。
- 用户必须明确选择初始化目标；多根 Workspace 不能默认猜测目录。
- Backend 使用 `git init`，不调用 shell，不修改全局 Git 配置。
- 初始化前拒绝文件路径、不可访问目录、Workspace 外路径和已经存在的 Git/SVN 仓库。
- 初始化成功后只重扫对应 Workspace，并自动选中新仓库。
- Git 不可用时入口由现有 Capability 禁用并显示原因。
- 失败时保留当前 Workspace 和界面状态，返回结构化错误。

### 4.2 Clone Repository

当前欢迎页没有 Clone URL、目标目录和真实 Clone 流程。

V5 需要：

- 欢迎页提供 Clone Repository，与 Open Workspace 并列，不改变现有欢迎页结构。
- 输入 Git URL 和本地父目录；目标文件夹名从 URL 推导但允许修改。
- Backend 校验 URL、父目录、目标名称、目标不存在或为空，并使用 argv 调用 `git clone`。
- 支持 HTTPS、SSH、本地路径和 `file://`；拒绝以选项形式注入的 URL 或目标。
- Clone 使用现有 OperationEvent、超时、取消和进程树终止能力。
- 不在命令行、事件、日志、诊断报告或错误中泄露 URL userinfo、Token 和密码。
- 首版认证沿用用户 Git Credential Helper 和 SSH Agent，不新增明文凭据输入框。
- 成功后在当前窗口打开，也允许用户选择在新窗口打开。
- 失败或取消后只清理由本次 Clone 创建且确认未完成的空目标；不得删除用户原有目录。

### 4.3 提交信息历史

当前 Commit 输入框没有插件中的历史记录入口。

V5 需要：

- 按当前选择的提交目标仓库读取最近提交信息。
- 多仓库时合并结果，按提交时间倒序、规范化换行、去空、去重。
- 默认最多显示 50 条，Backend 单仓库最多读取 100 条，避免扫描完整历史。
- 提供键盘可访问的历史按钮和 Dialog，选择后回填但不自动提交。
- 切换 Workspace、仓库选择或关闭 Dialog 时取消旧请求并丢弃旧结果。
- SVN 提交信息也纳入同一入口；Git/SVN 原始错误继续使用结构化错误模型。

### 4.4 复用最后一次提交信息

Amend 与“复用最后一次信息”不是同一功能。

V5 需要：

- 单仓库提交目标提供 Use Last Commit Message。
- Git 读取 `HEAD` 完整 message，SVN 读取当前 working copy 最新 revision 的 message。
- 多仓库目标不猜测来源；用户必须先选择仓库，或改用提交信息历史。
- 结果只填入输入框，不自动开启 Amend，也不改变文件选择。
- 无提交、无 HEAD 或 SVN 无日志时给出明确空状态。

### 4.5 Worktree 在 VersionDock 新窗口打开

当前 Worktree 菜单的 Open in New Window 最终调用系统 `open_path`，通常交给 Finder 或默认应用，名称与行为不一致。

V5 需要：

- Open in New Window 调用 VersionDock Desktop `openInNewWindow([worktreePath])`。
- Reveal/Open in File Manager 继续使用 Backend `reveal_items_in_dir`，两个入口不可混用。
- Worktree 路径必须来自 Backend 管理列表，并在打开前再次校验仍是该仓库的合法 Worktree。
- 已经在其他窗口打开时复用现有跨窗口聚焦逻辑，除非用户明确要求再开窗口。

## 5. P1：History 查询正确性

### 5.1 结构化 HistoryQuery

当前 `History` Bridge 只有 `filter: Option<String>` 和 `revision`；作者和日期主要在前端过滤已加载页面，Git 文本查询主要使用 `--grep`。

V5 新增 Rust/Specta 生成的结构化查询：

```text
HistoryQuery {
  text,
  author,
  fromDate,
  toDate,
  path,
  revision
}
```

要求：

- TypeScript Binding 由 Specta 生成，不手工编辑。
- Git 文本搜索统一覆盖完整 Hash、短 Hash、Subject、Body 和作者；不能只依赖 `--grep` 后再用当前页补救。
- 作者、起止日期和路径在 Backend 查询阶段生效，分页总是基于完整过滤结果。
- Git 路径筛选使用 literal pathspec，并支持 `--follow` 的文件重命名历史边界。
- SVN 路径筛选使用仓库内规范路径和 peg revision，不能拼接未验证 URL。
- `revision` 继续负责 Branch/Tag/Revision 范围，不与文本搜索混用为同一字段。
- 查询变化统一递增 generation、取消旧页和旧 topology 请求。

### 5.2 主 History 路径筛选

- History 工具栏增加 Path 筛选入口，可从当前工作树文件、Commit 文件或 File History 跳入。
- 显示规范化相对路径和所属仓库；多仓库时路径筛选必须绑定 repository。
- 清除路径筛选后恢复之前的仓库、Branch/Tag 和日期条件。
- 这属于提交历史的文件路径筛选，不实现选中行历史或 Blame。

### 5.3 Topology 与分页一致性

- 可能破坏图连续性的文本、作者、日期和路径查询使用过滤结果列表，不显示误导性的完整拓扑连线。
- 仅仓库或 Ref 筛选可继续使用对应 Backend topology。
- Load More 必须携带相同 HistoryQuery；查询变化后的旧分页不得追加。
- 作者筛选候选不再只从当前已加载页面统计；可由 Backend 返回候选，或明确标记为当前结果建议且允许自由输入。

## 6. P1：Pull/Update 后更新摘要

当前 Incoming/Unpushed 通知反映长期状态，但没有说明一次 Pull 或 SVN Update 实际带来了什么。

V5 需要：

- Git Pull 和 SVN Update 前记录轻量 revision/status 快照，成功后记录新快照。
- Git 计算旧 HEAD 到新 HEAD 的新增 Commit 和文件变更；fast-forward、merge 和无变化需要区分。
- SVN 计算旧 revision 到新 revision 的日志和 changed paths。
- 多仓库 Update Project 保留每个仓库的成功、无变化和失败事实。
- 结果通知显示新增 Commit 数和文件数，并提供 View Update Details。
- 详情复用现有 Commit Detail/聚合 Changes，不新增第二套 Diff 页面。
- Fetch 和 Push 不生成 Pull/Update 摘要。
- 摘要收集失败不能把已经成功的 Pull/Update 标记为操作失败；应返回“更新成功、摘要不可用”。

## 7. P1：提交信息编辑体验

### 7.1 Edit Commit Message

- 保留现有历史操作和安全校验，只将短 Prompt 升级为可调整大小的多行 Dialog。
- 显示目标仓库、Commit 短 Hash 和当前完整 message。
- 支持 `Cmd/Ctrl+Enter` 确认、Escape 取消、焦点陷阱与关闭后焦点恢复。
- 不引入 VS Code Editor Tab。

### 7.2 Squash Commit Message

- Squash 确认界面显示所选 Commit 列表、顺序和最终 message。
- 默认 message 由现有规则生成，用户可以在多行编辑器中修改。
- 执行前继续应用 clean worktree、HEAD、Detached 和进行中操作 Capability 校验。
- 失败后保留用户编辑内容和所选 Commit，便于修正后重试。

## 8. P2：GitHub/GitLab Provider 与发布

Provider 工作量和网络安全边界较大，不阻塞 P0/P1 本地功能发布。

### 8.1 Provider 账号模型

- 支持 GitHub.com、GitLab.com 和自建 GitLab。
- GitHub 优先使用 OAuth Device Flow；GitLab 首版可使用 PAT。
- Token 只存系统安全存储，状态文件只保存 Provider 类型、Host、账号显示信息和安全存储引用。
- Token 不进入 URL、Git argv、日志、事件、通知和诊断报告。
- 提供 Add、Reauthenticate、Remove；删除账号同时删除对应安全存储项。
- 自建 Host 只允许 `https`，开发测试例外必须显式配置，不允许静默跳过 TLS 校验。

### 8.2 浏览、搜索和 Clone 远程仓库

- Provider 返回分页仓库列表，支持名称/Namespace 搜索、私有标记和默认分支。
- 选择结果进入统一 Clone 流程，不建立第二套 Clone Backend。
- API 请求可取消、有超时、有分页上限，并对 401、403、429 和网络失败返回稳定错误码。

### 8.3 创建远程仓库和发布已有仓库

- 用户选择 Provider、Namespace、名称、描述和 Public/Private。
- 创建前检查本地仓库无 Remote、存在 HEAD 且不处于 Detached 状态。
- API 创建成功后再次检查 Remote；若期间已经出现 Remote，不覆盖用户修改，也不删除已创建的远端项目。
- 配置 `origin` 后可选择 Push，并复用现有 Remote 和 Sync Backend。
- 远端创建成功但本地配置或 Push 失败时返回分阶段结果和恢复建议，不假装原子回滚。

## 9. P2：可选网络头像

在线头像不是核心功能，默认保持当前本地彩色首字母。

若实施，需要：

- 设置项明确开启后，GitHub noreply 邮箱可解析 GitHub 用户头像，其他邮箱可选择 Gravatar。
- 不向网络发送作者姓名、仓库地址、Commit message 或本地路径。
- Gravatar 只发送规范化邮箱的哈希，不发送明文邮箱。
- 设置关闭、离线、超时、404 或图片失败时立即回退首字母。
- 限制并发、缓存数量和缓存期限；Workspace 切换不重复请求同一头像。
- CSP 和 Tauri 网络权限只开放所需 HTTPS Host。

## 10. P2：SVN 认证来源与原生缓存

当前 Desktop 系统安全存储已经比插件的明文或原生缓存管理更安全，因此本项不阻塞 V5 核心完成。

后续可补：

- 显示当前账号 Realm、用户名和来源：VersionDock Secure Store、SVN Native Cache 或 Session。
- 支持清除当前仓库对应的 SVN Native Cache，不提供无范围的全局清空。
- 切换账号前取消当前认证请求并清理进程内 Session 缓存。
- 不读取或展示缓存中的明文密码。
- 找不到安全存储或 SVN stdin 能力时继续明确降级，不回退为命令行密码参数。

## 11. 公共契约与实现约束

### 11.1 建议新增契约

- `BridgeCommand::InitializeRepository`
- `BridgeCommand::CloneRepository`
- `BridgeCommand::RecentCommitMessages`
- `BridgeCommand::LastCommitMessage`
- `HistoryQuery`
- `UpdateSummary`、`RepositoryUpdateResult`、`UpdateDetail`
- P2 实施时再增加 `RemoteProviderAccount`、`RemoteRepositoryPage` 和 `PublishRepositoryResult`

所有公共类型先修改 Rust/Specta，再生成 TypeScript Binding；禁止手工修改 `src/bindings/generated.ts`。

### 11.2 并发、取消和刷新

- Initialize、Clone、Pull/Update、Publish 使用现有 Operation Coordinator。
- Clone 和网络 Provider 请求必须支持等待许可阶段取消。
- 新仓库出现或 Clone/Init 完成后允许发送 `workspaceSnapshot`；提交信息和 History 查询不得重扫 Workspace。
- Update Summary 只更新目标仓库的 status、refs/history、conflicts、unpushed 和详情数据。
- 多窗口对同一路径 Clone/Init/Publish 必须去重或由 Backend 锁保护。

### 11.3 安全

- 所有路径使用 canonical parent + relative child 校验，拒绝 `..`、符号链接逃逸和 option-like 参数。
- 所有 Git/SVN 调用使用 argv，不经 shell。
- Clone URL、Provider Header、Token、PAT、OAuth response、错误和诊断报告统一脱敏。
- Provider 凭据只进入系统安全存储和内存；测试使用内存实现。
- 对已存在目录、Remote 和远端项目的操作不得做未确认覆盖或删除。

## 12. 测试要求

### 12.1 Rust 与真实 fixture

- Git Init：空目录、中文/空格路径、已有 Git/SVN、Workspace 外路径、取消。
- Clone：HTTPS/SSH 参数构造、本地 `file://`、目标冲突、URL userinfo 脱敏、取消和进程树清理。
- Commit Message：Git 多行 message、SVN message、多仓库排序去重、无 HEAD/无日志。
- HistoryQuery：文本、Hash、作者、日期、Ref、Git rename path、SVN path、分页和旧 cursor/context 拒绝。
- Update Summary：无变化、fast-forward、merge、SVN revision、摘要失败但更新成功、多仓库部分失败。
- Worktree：新窗口使用受管路径，非法或已经移除的 Worktree 被拒绝。
- Provider：内存凭据、分页、限流、认证失败、Host 校验、远端创建后的本地分阶段失败。

### 12.2 前端

- Welcome 页 Init/Clone 可用性、表单校验、取消和成功打开。
- Commit Message History 加载、去重、回填、旧请求丢弃和键盘操作。
- Last Commit Message 单仓库边界，不改变 Amend 和文件选择。
- History 所有条件由请求参数驱动，Load More 保持相同查询上下文。
- Update Summary 通知、详情入口、无变化和部分失败。
- Edit/Squash 多行 Dialog 的焦点、键盘、长文本和失败保留。
- Worktree Open in New Window 与 Reveal 的调用严格区分。
- Provider 设置、搜索、发布分阶段结果和 Token 不进入可见错误。
- 在线头像关闭、失败回退、缓存和隐私设置。

### 12.3 持续门禁

每阶段至少执行：

```text
npm run bindings
npm run bindings:check
npm run check
git diff --check
```

涉及真实 Git/SVN 行为时运行临时仓库 fixture。网络 Provider 测试使用本地 Mock HTTP Server，不依赖真实用户账号，不在 CI 使用生产 Token。

## 13. 实施顺序

1. Initialize Repository、Clone Repository 和欢迎页入口。
2. Recent Commit Messages、Last Commit Message 和 Commit 表单交互。
3. Worktree 真正的新窗口行为。
4. HistoryQuery、Backend 筛选和主 History 路径筛选。
5. Pull/SVN Update 前后快照、通知和 Update Details。
6. Edit/Squash 多行提交信息 Dialog。
7. SVN 认证来源和原生缓存管理。
8. GitHub/GitLab Provider、远程搜索、创建和发布。
9. 用户明确需要时再实施可选网络头像。

每一阶段完成后关闭旧路径，不保留 Mock 或长期并存的第二套契约。P0/P1 通过后可以单独形成一个不含 Provider 的本地功能版本，P2 网络能力不得阻塞它。

## 14. 最终验收标准

V5 代码完成时必须满足：

- 空目录可以安全初始化 Git，Clone 可以取消且不会误删用户目录。
- 提交信息历史和最后一次提交信息支持 Git/SVN，并且不会自动提交或改变 Amend。
- Worktree 的新窗口和文件管理器入口名称与行为一致。
- History 文本、Hash、作者、日期、Ref 和路径筛选在完整 Backend 结果集上生效，分页不漏项、不串上下文。
- Pull/SVN Update 后能说明本次新增 Commit 和文件变化，摘要失败不改变更新成功事实。
- Edit/Squash 支持长提交信息和失败恢复。
- Provider Token 只存在于系统安全存储和请求内存，任何日志、错误和诊断均不泄露。
- GitHub/GitLab 创建远端成功而本地失败时，界面保留真实分阶段结果和恢复入口。
- 在线头像始终可关闭，失败时不影响 History 和 Commit Detail。
- AI、Ghost Text、Blame 和 VS Code 宿主能力没有进入 V5 产品入口。
- 完整自动化继续通过，实际执行的平台记录 Runtime 证据；未执行平台如实标记。

V5 的“本地功能完成”和“网络 Provider 完成”可以分阶段记录；在 P2 未完成前不得宣称 GitHub/GitLab 发布闭环完成，但不影响 P0/P1 本地功能验收。
