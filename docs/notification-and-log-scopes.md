# 通知与日志的范围

底部入口属于当前应用窗口。通知用于查看操作结果，日志用于排查具体项目和操作；不为每个标签重复创建入口。

## 通知

- 角标汇总窗口内全部未读，通知中心默认显示全部，始终提供“全部 / 当前项目 / 应用”筛选。
- 通知创建时记录工作区 ID、名称和路径，关闭项目后仍可辨认来源。未指定工作区时继承操作上下文；应用级通知明确传入 `workspaceId: null`。
- “标为已读”和“清空”仅作用于所选范围。当前项目不混入应用通知。
- “查看日志”不切换工作标签，直接选择来源项目或应用日志，清除遗留的频道、级别和文本筛选。有操作编号时只显示该操作，可通过“查看项目全部日志”解除限制。

## 日志

- 默认跟随当前项目；也可选全部、应用及已知项目。关闭标签不会丢失仍有通知或日志记录的项目来源。
- 有工作区 ID 的日志优先按 ID 归属；旧记录按工作目录匹配。没有工作区 ID 和工作目录的记录归应用。
- 已读按面板实际筛选展示的记录 ID 更新，打开面板本身不会清除其他范围的错误角标。
- “清空当前筛选结果”捕获当时的记录 ID，通过 Bridge 和 Rust 清理内存中的对应记录；不影响其他项目、隐藏结果或之后新增的日志。失败时恢复被清理记录及其已读状态。
- 清空输出不删除磁盘历史日志，沿用原有行为。复制与导出继续只作用于当前筛选结果。
- 普通日志正文、时间、级别、频道、项目及退出码允许直接选中复制，可跨行选择；详情仍可单独选中。工具栏和详情展开按钮不参与文本选择，大量日志的全部筛选结果可使用工具栏“复制日志”。

## Fetch 后的刷新

- 自动、启动和手动 Fetch 共用仓库级刷新合并。抓取期间先积累分支、历史和传入/传出提交的刷新需求，完成后统一读取；文件状态变化与其他仓库继续正常刷新。
- `FETCH_HEAD` 在没有新提交时也会被 Git 重写，因此单独变化不触发历史刷新。外部工具更新远程分支、标签或 `packed-refs` 时仍由文件监听刷新。
- Fetch 完成通知和文件监听共用待刷新队列，不再额外扫描整个工作区。失败或取消后仍读取最终状态，保留已更新的部分引用；切换工作区后不把旧结果写入新标签。
