# 主题基础配色

`src/styles.css` 的八套主题同时作用于应用根节点和设置中的 `.theme-preview-surface`。基础色按主题来源映射；页面不再用同一个 `surface-alt` 代替标题栏、状态栏和按钮的不同颜色角色。

## 来源与范围

2026 深浅主题参考 [VS Code 官方默认主题](https://github.com/microsoft/vscode/tree/main/extensions/theme-defaults/themes) 的 `2026-dark.json` / `2026-light.json`，并解析其继承的 Modern 主题。经典深浅主题对应 Dark+ / Light+；主题未声明的标题栏、蓝色状态栏、输入框等颜色参考 VS Code 的默认颜色注册。

其余四套主题采用项目锁定的 Shiki 3.23.0 中相应主题的工作台颜色，并核对上游定义：

- [GitHub Dark Dimmed](https://github.com/primer/github-vscode-theme)
- [One Dark Pro](https://github.com/Binaryify/OneDark-Pro)
- [Dracula](https://github.com/dracula/visual-studio-code)
- [Nord](https://github.com/nordtheme/visual-studio-code)

本次核对日期：2026-10-15。以上是维护来源，不在应用运行时访问网络或读取本机 VS Code。升级主题来源时应重新核对继承项及未声明项；不把主题未声明的颜色误当成另一套主题的默认值。

| 界面角色 | 变量与消费位置 |
| --- | --- |
| 标题栏 | `--vscode-titleBar-*` 用于背景与普通图标文字；分隔线使用应用语义边框 |
| 状态栏 | `--vscode-statusBar-*` / `--vscode-statusBarItem-*` 用于背景、普通文字、悬停和按下；分隔线使用应用语义边框 |
| 侧栏、编辑区 | `--versiondock-surface` / `--versiondock-bg`，对应主题的侧栏和编辑器背景 |
| 主次操作按钮 | `--vscode-button-*`，由 `buttons.css` 和分段按钮容器管理 |
| 输入与搜索框 | `--vscode-input-*` 保留基础色来源；边框与占位文字使用公共控件变量 |
| 下拉触发器 | `--vscode-dropdown-*` 保留背景与文字；边框使用公共控件变量 |

主题未定义的按钮悬停使用 VS Code 默认派生规则。官方的透明边框、与背景相同的边框不能直接作为应用控件边界：本应用的设置行、卡片及分段按钮布局与 VS Code 不同，照搬会导致控件与周围内容混在一起。

## 文字与按钮可读性

- 普通小字号文字以 WCAG 对比度至少 4.5:1 为目标。检查正文、说明及弱化文字在编辑区、侧栏、卡片、输入和悬停背景上的实际颜色；透明背景先与底色合成。普通正文色保留主题定义。
- `--versiondock-muted` 按主题调整，`--vscode-descriptionForeground` 和 `--versiondock-faint` 复用该可读文字色。弱化标签、路径、时间和行号不能借用禁用色；`--vscode-disabledForeground` 单独保留各主题原有的弱色，禁用控件仍由公共组件管理透明度。
- GitHub Dark Dimmed 主按钮保留绿色，将白字悬停背景调整为 `#3a833f`；次按钮悬停也保留足够文字对比度。One Dark Pro 的灰色主按钮、Nord 的亮色主按钮及深色文字继续保留。
- `--vscode-textLink-foreground` 由主题强调色和正文色派生，供链接按钮使用；聚焦、选中和边框继续使用原来的强调色，避免为了链接可读性改变所有选中效果。
- 实色危险按钮使用独立的 `--versiondock-danger-button-background`、`foreground`、`hover-background`、`pressed-background` 和 `border` 配色。深色主题加深原有危险色，浅色主题保留已有深红底，搭配白字；菜单、图标和文本提示的危险色保持各自语义。
- 按钮按下色从默认和悬停背景派生，实色危险按钮使用专用按下色；避免向背景混入白色文字后降低对比度。主、次和危险按钮均检查默认、悬停、按下及键盘聚焦状态，禁用状态单独验收。
- 公共变量同时在应用根节点和主题预览作用域定义，预览必须使用自身主题的颜色，不能继承当前应用主题计算后的按钮色。

## 边界可见性

- `--versiondock-border` / `--versiondock-border-soft` 是应用语义色，分别用于面板边界和内部细分隔线；允许在官方基础色板上适度增强。所有主题均定义，2026 浅色也不能用接近白色的线代替必要分隔。
- `--versiondock-control-border` 由当前主题正文色与语义边框混合，统一用于普通输入、搜索、多行输入、下拉触发器和次按钮。正常状态保持可见，不依赖鼠标悬停才能发现控件。主题预览在自身作用域解析变量。
- `--versiondock-primary-button-border` 由主按钮背景与文字成对派生，用于普通主按钮和分段主操作；提交按钮不能再把边框强制设为透明。
- `--versiondock-control-placeholder` 由主题正文色和输入背景派生，避免占位文字随官方弱色一起消失。提交输入和公共输入复用同一变量。
- 所有边框仍为 1px，搜索框只保留外层边界，分段按钮只由容器管理外框；展开图标和轻量操作不增加边框。
- 悬停、聚焦、错误、只读和禁用各自保留语义，不能用默认边框覆盖焦点色或错误色。控件边框的计算色与输入/下拉底色应至少达到 3:1；面板细分隔线单独检查层次，不机械使用控件的强度。

## 应用保留的交互语义

这是基础色对齐，并非完整复刻 VS Code 的布局与全部工作台状态：

- 聚焦、标签下划线、选中条目、复选框和开关继续使用已统一的主题强调色。主按钮与强调色分开；例如 GitHub 主按钮为绿色，选中与焦点仍为蓝色。Nord 主按钮使用深色文字，不影响复选框的白色勾选标记。
- 菜单、危险操作及 Git / SVN 增删改保留现有对比度调整，不用官方较弱的颜色覆盖已经修正的可读性。
- 普通图标悬停及按下根据主题正文色生成中性反馈；展开箭头仍无背景。状态栏使用独立的官方悬停色。
- 分支同步、拉取、推送、工作区修改使用主题的强调色、成功色和修改色。经典主题蓝色状态栏使用白色分支文字，状态由原有图标、数字和提示表达。
- 状态栏警告背景与文字成对定义，默认由警告色和主题表面混合；Nord 使用官方黄底深色字。进度、更新及错误仍保留各自业务语义。
- 窗口激活与失焦不新增另一套监听或状态逻辑；本次对齐正常显示的标题栏和状态栏配色。

验收时切换全部八套主题，并交叉检查深浅主题、中英文、主次按钮悬停、输入框聚焦、状态栏警告及设置中的其他主题预览。浏览器渲染验收与 Tauri 原生验收分别记录。
