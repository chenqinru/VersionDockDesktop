# 仓库操作调度

本地写操作优先于自动获取远程引用，Git / SVN 的仓库写入串行保护保持有效。

- 启动、窗口聚焦及定时触发的自动 Fetch 使用 `RequestContext.target = autoFetch`，并保留 `background` 可见性。仅隐藏进度不代表自动任务，手动 Fetch 不带此标记。
- Rust 调度器按仓库登记自动 Fetch 和前台写操作，跨窗口统一生效。前台写操作在排队前取消同仓库已经运行或等待中的自动 Fetch；存在前台写操作时，新自动 Fetch 直接取消。
- 取消通过已有 `CancellationToken` 传递给 CLI，终止 Git 进程树并等待进程退出。仓库写锁在清理返回后才释放，后续暂存、提交等操作不会提前执行。
- 自动 Fetch 使用独立的 2 个并发名额，前台写操作仍使用原有 2 个名额，读取许可保持独立。同仓库仍共用一把写锁，其他仓库的慢速自动 Fetch 不占用前台写名额。
- 活动登记使用生命周期守卫，完成、取消和丢弃请求时均清理，避免旧任务释放新任务的登记。用户取消排队操作后，只有仍有其他前台写请求时才继续阻止新自动 Fetch。
- 手动 Fetch、Pull、合并及其他用户写操作继续串行排队，保留现有取消能力；不通过删除 `index.lock` 或放开并发写入绕过等待。

原生等待状态沿用操作进度机制。正在停止自动 Fetch 时显示明确原因，并内置中英文翻译。

回归包含本机 TCP 服务故意不回应的真实 Git Fetch：用户提交会取消该传输，确认传输连接关闭后创建提交，并核对提交内容、工作区及锁文件。测试只使用临时仓库，不访问生产远程仓库。

仓库读取保持最多 4 个并发：3 个公平共享名额，以及 1 个只供交互读取使用的名额。点击 Diff、提交详情、文件历史或分支比较等请求优先使用交互名额，也可使用空闲的共享名额；后台列表、状态及预读使用共享名额。后台达到并发上限时，仍能立即接纳一个交互读取。交互名额已经占用时，后续请求仍可能等待；不会强制中断正在执行的读取。共享队列沿用公平排队，避免后台任务长期得不到执行。

读取优先级通过请求信封的 `readPriority` 传递，与任务进度可见性分开。`RequestOptions.readPriority` 可覆盖按命令推断的默认值；历史悬停预读和同步页批量搜索详情明确使用 `background`。旧信封缺少此字段时按后台读取处理。排队中的读取继续使用原有取消和超时机制，取消或丢弃请求会释放排队位置。

保留在隐藏页签中的仓库面板不再主动补读缺失列表；重新显示时检查并补读。同步页的提交展开详情、批量搜索和聚合文件读取会随隐藏取消，旧响应不能覆盖当前结果；已经完成的缓存与展开状态继续保留。工作区级刷新、标签计数和正在执行的写操作继续独立运行，避免暂停视图影响仓库状态的正确性。
