# 多仓库任务与检查点

打开项目后，从窗口顶部入口或底部状态栏的“检查点”打开“任务与检查点”；欢迎页不显示检查点按钮。中心按项目汇总全部任务，选择任务不切换主窗口工作区；底部状态栏仍显示当前工作区的记录状态。检查点记录真实 Git 仓库的文件与暂存状态，普通项目父目录本身不需要 `.git`。

状态栏显示待记录、记录中、已完成、待收尾、已撤销及异常等状态；优先展示待恢复、异常和进行中的任务，多个任务同时记录时附带数量，点击可定位对应任务。关闭面板后每三秒通过轻量元数据接口更新，窗口重新获得焦点时立即刷新。该接口不读取快照正文、不补算文件摘要、不统计磁盘占用，也不等待 Git 写锁或快照清理锁。读取失败时显示异常，避免把旧数据当成最新状态。

“记录中”表示当前检查点区间尚未结束，不代表 Codex 仍在执行。手动模式需要点击“结束记录”，自动模式由 Hook 结束事件完成记录。

## 日常开发：原目录模式

1. 新建任务，填写名称并选择需要保护的 Git 仓库。默认使用“原目录”和“手动记录”。
2. 开发前点击“开始记录”，继续在已有 Codex 项目中开发，无需新增项目入口或重装依赖。
3. 确认 Codex、终端后台程序和编辑器停止写入后，点击“结束记录”。
4. “撤销最近一轮”及记录行中的撤销按钮在列表页直接检查全部仓库，不打开“查看更改”；选择较早记录会连同后续已完成记录一起撤销。
5. 检查通过后直接弹出二次确认，显示实际撤销轮数及文件数；确认后执行。若任何仓库存在冲突，则在原页显示问题，全部仓库保持不变。

“查看更改”和撤销预览按仓库分组列出文件，工作区与暂存区分别标注。点击文件后，右侧使用工作台现有 Diff 视图显示行号、增删高亮与代码高亮，支持行内和并排查看。比较内容来自检查点或撤销预览的快照，不读取文件当前内容替代历史状态。二进制和超大文件显示明确提示。

同一批原目录只能登记一个保护任务，同一个任务同时只记录一个区间。期间发生的人工修改也属于该区间；工具不能把共享目录中的外部写入自动归属于某个人或聊天。多个聊天需要同时开发时使用隔离模式。

## 并行开发：隔离任务模式

每个任务为选中的每个仓库创建独立 worktree 和 `codex/` 分支，保留项目根内的相对路径。已有暂存、未暂存和非忽略的未跟踪内容会复制到任务起点，原目录保持不变。

在任务标题右侧的齿轮中打开“任务设置”，使用“复制 Codex 项目路径”，将任务目录添加为 Codex 的本地项目。每个聊天使用一个不同的任务目录，不要再通过 Codex 只隔离其中的主仓库。依赖和忽略配置不自动共享；创建时可用绝对文件路径明确选择需要复制的本地配置，以分号分隔。复制的忽略文件仍不受检查点保护。

“预览带回原目录”将任务的净变化合并回源工作区。它会保留源暂存区，不自动提交、推送或合并分支。后续再次带回仅处理自上次带回后的变化。带回操作本身有“撤销带回操作”入口。

任务路径旁的“打开任务”保留外链图标，菜单提供“在 Codex 中打开”“在当前窗口打开”和“在新窗口打开”；旁边仍可复制 Codex 项目路径。当前工作区的目录集合与任务根目录一致时，禁用当前窗口打开。

“在 Codex 中打开”使用单色 Codex 图标。macOS 通过 Launch Services 定位已安装的 Codex 应用，优先使用应用自带 CLI 执行 `codex app <任务目录>`，无需在 Finder 的 PATH 中配置 npm；后端根据任务 ID 验证所属项目，只传已登记的绝对目录，不拼接 shell 命令。应用未安装、目录不可用、启动失败会在面板内显示，可取消启动请求；不安装应用、不发送消息、不绑定之前的聊天。Windows/Linux 的此菜单项明确标为暂不支持，其余打开方式保持可用。

`docs/manual/screenshots/checkpoint-open-task/` 包含浏览器展示数据下的中英文、深浅主题菜单、当前窗口禁用、Codex 启动失败及不支持平台提示。独立标识的 Tauri 验收实例通过界面触发已登记任务的真实启动，调用已安装应用的自带 CLI 并收到退出码 0；目标使用 Codex 已有项目目录，未发送消息或执行源仓库写操作。`native-result.json` 记录实际命令与结果，只证明启动交接成功，不声称定位到某个聊天。Rust 测试另覆盖任务所属项目验证、中文和空格及 shell 字符路径、失败结果和取消启动。

## 区分检查点记录

在“任务设置”标题旁点击铅笔可重命名任务，名称为 1 至 100 个字符的单行文本。保存后侧栏及页面标题同步更新，只修改名称，不改变任务目录、分支或检查点；有待恢复操作时需先完成恢复。

新自动记录以发送消息的第一个非空行作为标题，最多显示 50 个字符；点击记录右侧的消息按钮可展开查看完整正文。旧记录和手动记录继续以自定义名称或变更文件名作为展示标题，下方显示去重后的文件数和最多两个仓库路径。每条记录附有基于其 ID 的短编号，清理旧历史后不会重新编号。旧记录会从已有快照生成同样的摘要；正在记录时可先通过编号和时间区分。

记录行的铅笔按钮支持重命名，名称为 1 至 100 个字符的单行文本。自定义名称优先展示，重命名不改变检查点起止快照或撤销内容。文件摘要只比较快照清单。消息来自开始事件的 `prompt` 字段，不读取聊天记录；重命名只修改标题，原消息仍保留。

## 自动记录 Codex 修改

在“任务设置”中选择“自动记录”，然后点击“安装 Codex 检查点 Hooks”。也可从侧栏底部的“Codex 接入”查看安装和连接状态。安装会备份现有的 `hooks.json`，合并 VersionDock 自己的处理程序并保留其他已有处理程序。

根据 [Codex Hooks 官方说明](https://learn.chatgpt.com/docs/hooks)，需要在 Codex 中审阅并信任新增或更新后的 Hooks，并按客户端需要重载会话。配置安装成功不代表当前桌面端已经兼容。

- `UserPromptSubmit`：在开始一轮修改前保存基线，使用会话和轮次标识防止重复记录。
- `Stop`：保存结束状态。结束事件失败只发出告警，不触发 Codex 自动继续运行。
- `Interrupt`：只快速标记为待收尾。同一聊天再次发送消息时，先拍摄稳定状态，以同一份快照完成旧检查点并开始新检查点，保留暂停前的修改；也可确认写入停止后手动结束记录。
- 自动接续仅适用于同一聊天中已收到中断标记、起始快照完整的记录。快照失败保留旧记录并阻止本次发送；缺少中断标记、记录不完整或手动记录未结束时，需在 VersionDock 手动处理。
- 重叠会话的开始事件会被阻止；不同隔离任务可以并行。

暂停并不保证后台程序全部退出，再次发送前应停止向受保护目录写入。稳定快照检测只覆盖拍摄期间，不能阻止外部程序之后继续写入。暂停到重发之间的人工修改也会计入旧检查点，工具无法自动区分这些修改的来源。旧轮次迟到的结束或中断事件不会关闭新轮次的记录。

首次接入请执行一个简短的新增文件任务，确认面板收到了开始、结束事件，出现一条已完成记录，再预览并执行撤销。CLI 功能开启、人工发送的测试事件都不能代替这个桌面端验证。未收到完整事件、事件标识缺失或快照失败时，面板显示未验证或错误；请切换手动模式。

Hooks 调用应用可执行文件的无窗口入口，因此 VersionDock 窗口关闭后仍能记录。只处理已登记的任务路径，不解析聊天记录。新自动检查点会在本地保存发送消息正文，按内容哈希去重；同一会话、同一轮次中收到不同正文时追加到该检查点，不重拍起始快照。重复正文只保存一次；官方 Hooks 未提供稳定消息 ID，因此无法区分有意重复发送的相同正文与事件重投。列表仅返回消息引用，展开记录时才读取全文。清理或移除检查点后，仅回收不再被其他记录或恢复备份引用的消息数据。旧记录没有消息正文，无法补回。移动、更新应用或改变安装路径后，应重新安装并信任 Hooks。

## 恢复保障与边界

- 工作区文件和暂存区分别记录；不使用 `reset --hard`、`clean`、`stash push` 或临时提交制造基线。
- 文本文件采用逐轮反向三方合并，保留记录结束后以及两轮之间不重叠的手动修改。
- 新增与删除、二进制、链接、文件类型及权限变化存在后续冲突时，不强制覆盖。
- 操作前预检全部仓库并验证预览指纹。预览后有变化需要重新预览。
- 写入前持久化恢复记录；部分写入失败后，在“恢复操作需要处理”中恢复操作前状态。已有其他写入冲突时，保留恢复记录并说明具体路径。
- 多仓库不具备文件系统级原子事务；恢复期间应停止外部写入。VersionDock 的锁不能阻止不遵循这些锁的编辑器或脚本。
- 第一版不回退提交历史，不支持记录区间内检出、提交、merge/rebase 等 HEAD 或分支变化。子模块、相互嵌套的仓库、稀疏索引和 assume-unchanged 文件暂不支持。
- 新仓库没有初始提交、存在未解决冲突或有正在进行的 Git 操作时，无法创建任务。
- 只保护所选仓库中的文件；项目父目录辅助文件、忽略文件和空目录不属于撤销范围。

快照保存在应用配置目录下的 `checkpoints`，按内容去重，不自动过期。原目录任务移除时只删除登记及检查点历史。隔离任务须先带回成果或恢复至起点，且先移走忽略文件，才能移除 worktree；任务分支保留。失败创建的登记可以移除，但已创建的 worktree 和辅助文件保留，避免丢失可能已写入的内容。

## 重做与未结束记录

普通撤销成功后，任务标题区提供“重做上次撤销”。点击后在列表页预检全部仓库的反向三方合并，通过后直接二次确认，显示重新应用上次撤销的修改及涉及的文件数，不再打开预览页。取消保留列表且不写入；冲突及无实际变更在当前页显示，不发起确认。有冲突则整批暂停，预检失效需重新检查。执行时保留撤销之后不重叠的工作区与暂存区修改，使用与撤销相同的恢复备份及逐项写入保护，部分失败可恢复到重做前状态。确认期间切换项目或任务、关闭面板或替换预检结果后，旧确认不能执行。

第一版只重做最近一次成功的普通撤销，不提供多层重做栈；新记录、带回成果或后续成功操作会使旧重做入口失效。仍可重做的记录和备份受到清理保护。重做后原检查点恢复为已完成，可再次撤销。

列表只在任务标题区保留“重做上次撤销”，各记录行不重复添加按钮。查看已撤销记录时，只有该记录属于后端返回的当前可重做范围，底部才将不可用的撤销按钮替换为“重做上次撤销”，并提示恢复上次撤销的全部轮数；不推测其他已撤销记录也可重做。详情内重做预检、取消或冲突均保留历史 Diff，不重新加载已显示文件；确认后执行整次重做。

`docs/manual/screenshots/checkpoint-detail-redo/` 使用浏览器展示数据验证同一次撤销中两轮记录均可重做、较早的其他撤销不可重做、取消和冲突保留 Diff，以及中英文、深浅主题和窄窗口。后端临时 Git 仓库测试验证列表与概览返回同一实际撤销范围、其他项目隔离，以及重做后可重做范围失效。

另在独立应用标识的真实 Tauri 实例中，对临时 Git 仓库完成“打开已撤销记录详情 → 重做预检 → 取消 → 再次预检并确认执行”：取消保留详情和文件，确认后恢复被撤销的文件内容，Git 暂存区字节不变，记录恢复已完成、重做事务成功。证据为该目录中的 `native-confirmation.png`、`native-completed.png` 和 `native-result.json`；未修改用户项目或全局 Codex Hooks。

`docs/manual/screenshots/checkpoint-inline-redo/` 使用浏览器展示数据验证列表页直接确认、取消保留列表、冲突原页显示，以及中英文和深浅主题；重做预检后未额外请求历史概览、文件清单或 Diff。行为测试另覆盖确认后执行、空结果、预检失败、取消后迟到结果，以及切换任务、关闭面板和替换预检后的旧确认失效。本轮未重新执行原生 Git 重做验收。

未结束记录显示名称、开始时间、持续分钟数及最近 Hook 时间；超过 10 分钟提示检查写入状态。只提醒，不自动结束。停止文件写入后可选择结束、放弃或查看连接详情。手动模式与自动模式均保留明确的收尾入口。

## 清理旧检查点

在“任务设置 → 快照存储”可按需查看全部项目的快照总量、当前任务引用量（含共享内容）和全部可清理历史预计释放空间，并打开原生快照目录。各任务引用的共享内容不可直接相加。总量超过 1 GiB 时显示手动清理提醒，不默认删除历史；页面底部明确快照由全部项目共享，空项目不再把全局占用显示成该项目占用。

在该区域选择保留最近 10、30、100 条记录，或清理全部可清理历史，然后点击“预览清理”。预览列出将删除的记录数、受保护记录数，以及按实际共享引用计算的预计释放空间。确认后才执行，任务和项目文件保持原样，删除的历史无法恢复。

- 进行中、已中断或不完整的记录未结束时，不允许清理该任务。存在未处理的恢复操作时也会阻止清理。
- 隔离任务中尚未带回的已完成记录，以及仍可撤销的带回操作和相关历史受到保护，保留数量可能超过所选条数。
- 任务起点、带回基线、其他任务共用内容，以及恢复操作引用的数据始终保留。删除记录不一定释放全部对应空间。
- 清理会使该任务尚未执行的恢复预览失效，并清除已结束且不再需要的普通撤销操作备份。执行前再次核对预览指纹；任务或共享存储发生变化后需要重新预览。
- 先原子保存新的引用清单，再删除无引用文件。删除中断或失败时，会报告已删除记录数和实际释放空间；剩余无引用文件可再次预览清理，不会回滚已生效的历史删除。

清理引擎及命令分发使用临时真实 Git 仓库验证，覆盖工作区隔离、保留任务与代码、清理后撤销、共享引用、恢复备份、取消和存储失败。`docs/manual/screenshots/checkpoint-cleanup/` 为浏览器固定展示数据的深浅主题、中英文及确认弹窗检查；未用用户项目执行清理验收。

### 查看更改与撤销入口

查看检查点更改时默认展示第一个文件的差异，并收起任务侧栏及目录、记录方式和 Hook 诊断，顶部合并为一个信息区：突出检查点标题，任务名、时间、短编号、状态与更改数作为次要信息；顶部保留返回及消息入口，任务设置入口仅保留在外层任务页，撤销操作固定在底部右侧。有已保存消息时可以按需展开原文。文件列表优先显示文件名，次行显示目录与工作区/暂存区，完整路径通过悬停查看；分隔条支持拖动、方向键及 Home/End 调整宽度。

“撤销到此轮之前”位于查看更改页面底部右侧，针对正在查看的检查点，在原页执行全部仓库撤销预检，通过后直接二次确认，不再强制跳转到另一页。选择较早记录会同时撤销之后的已完成记录，确认中的轮数来自后端实际预检范围，文件数按仓库与路径去重。进行中、已撤销、待恢复及冲突状态阻止相应执行；确认期间关闭面板、切换工作区或任务、更换预览后，旧确认不能执行。

预检期间和取消确认后保留原有历史 Diff，不重复挂载或请求已显示的文件差异；撤销及重做预检完成也不额外刷新历史概览。冲突及无实际变更在原页显示，不发起确认或写入。页面始终展示本轮历史变更，不提供撤销效果切换；重试撤销会重新预检。成果带回仍使用预览执行流程。

外层“撤销最近一轮”及记录行撤销复用相同预检和确认逻辑，预检期间、取消及执行后均保持列表页，不请求历史文件清单或 Diff。冲突或无实际变更直接显示在列表页，想先阅读代码时可单独打开“查看更改”。

### 记录列表阅读与筛选

### 历史读取性能与并发

面板轮询只读取任务概览，不扫描磁盘占用或加载完整历史。历史按每页 50 条读取，可搜索名称和已保存的消息正文，并按仓库筛选；筛选不改变撤销范围。分页响应携带记录版本，版本变化后回到第一页，较早检查点的后续撤销数量由完整历史计算。只读元数据按文件修改时间、长度及 Unix 文件身份缓存；写操作始终在写锁下重新读取持久化状态。

历史列表、文件清单、消息和文件 Diff 读取原子发布的记录及不可变快照，不申请仓库写锁，也不等待自动记录持有的全局写锁。读取期间持有独立的共享快照生存期锁；清理历史、删除任务先获取全局写锁，再获取该锁的排他权限，确保不会删除正在读取的对象。撤销、成果带回和记录的写锁保持原有保护。

查看更改先返回仓库、路径、暂存/工作区及变更状态，文件清单加载后默认选中第一个文件并读取其 Diff，其他文件在切换选择时读取并校验。旧记录摘要以存储目录和前后快照哈希为键缓存于当前进程，最多 256 项，重启后按需重建；不改写旧记录或把摘要缓存当作恢复依据。查看更改期间暂停完整历史轮询，保留轻量状态轮询，打开成功后不立即重复刷新列表。读取中显示对应记录的加载图标及“正在加载更改文件”。

Debug 日志中的 `Checkpoint history read` 记录 `object_lock_ms`、`metadata_ms`、`work_ms` 和总时长，供区分清理锁等待、记录读取及后续计算；不记录文件正文和用户消息。

临时真实 Git 仓库测试覆盖三仓库写锁及自动记录全局锁被占用时历史读取仍可完成、正文按需验证、旧摘要缓存、快照清理等待多个共享读取者和取消后数据不变。浏览器加载态检查只证明前端反馈，不作为原生仓库读取性能数据。

本轮在真实 Tauri 开发窗口只读打开 `excellence-star` 的四文件历史记录，Debug 日志记录文件清单请求约 25ms、快照生存期锁等待 0ms；这是单次后端请求耗时，不包含界面渲染或作为普遍性能承诺。更改页停留期间未继续轮询历史。

任务侧栏在名称下显示目录模式及手动/自动记录方式；英文使用简短标签，窄侧栏允许换行，悬停可查看完整说明。底部 Codex 接入区分“未配置 / 手动记录 / 未安装 Hooks / 待验证 / 已验证 / 异常”。同一自动记录轮次的开始与结束成功后才显示已验证，事件名称的历史累计和配置安装本身不作为验证依据；状态与入口可一起点击查看设置。浏览器视觉证据位于 `docs/manual/screenshots/checkpoint-sidebar/`。

任务设置标题与返回入口合并为一行，并显示当前任务名。原目录模式保留复制路径，将两个打开入口收进公共“更多”菜单；隔离任务保持打开入口可见。Codex 接入紧接记录方式，状态和最近事件直接显示，说明与事件诊断默认折叠。清理预览为零记录且零可回收字节时仅显示空提示；存在可删记录或可回收字节时显示结果与确认清理按钮。移除区保留在末尾，并明确保留原项目文件。`docs/manual/screenshots/checkpoint-settings/` 为浏览器展示数据下的深浅主题、中英文、原目录/隔离模式、清理预览与窄窗口验收。

新建页对任务名称标注必填，失焦后提示空白名称；仓库列表显示项目内相对路径并保留完整路径悬停提示，全选/全不选只影响支持的 Git 仓库。已知同工作区或相同仓库的原目录任务会在提交前提示并阻止重复创建，可直接使用已有任务或切换隔离模式；后端仍负责完整并发及跨工作区校验。底部合并为存储信息、取消和创建任务，顶部关闭入口保留。浏览器深浅主题、中英文、必填校验、批量选择、原目录重叠及隔离模式的证据位于 `docs/manual/screenshots/checkpoint-create/`。

### 全局检查点中心

打开项目后，顶部 Title Bar 的旗帜入口打开同一个检查点中心，欢迎页不显示该入口。左侧只列出拥有检查点任务的项目，按项目分组显示任务名称和简短状态，项目头像复用欢迎页的字母、路径配色和可用性样式；当前项目默认展开，支持折叠及项目名、任务名搜索。点击任务只切换中心的查看对象，不切换主窗口工作区。

新建任务默认选择中心当前项目，可切换最近项目，或选择尚未打开的本地文件夹。切换项目保留任务名称、工作目录模式和记录方式，重新扫描并选择仓库；加载过程中不能提交，旧扫描结果不能覆盖新项目。选择文件夹仅登记检查点项目，不打开主工作区或添加主窗口标签；成功创建任务后才出现在侧栏。项目下拉列表独立滚动，到达边界不会带动外层页面。

中心使用独立的项目作用域，历史、消息、Diff、清理和撤销均携带所属项目 ID。底部状态栏独立轮询主窗口当前项目的状态，点击后定位同一中心的对应任务。全局目录只读取紧凑元数据，不扫描各项目代码或统计快照空间；详细历史和存储仍按需加载，所有检查点请求保持全局消息静默。

创建任务时另存原项目信息，不改变任务快照或恢复指纹。即使项目已移出最近列表，检查点仍可查看和管理；旧记录优先使用最近项目元数据，缺失时从记录中的原目录信息恢复显示。后端保留项目归属校验，不能用项目 A 的请求操作项目 B 的任务。

### 全局设置与项目存储管理

检查点中心左侧栏底部固定显示“检查点设置”，管理全局 Hook 安装、更新、使用说明，以及全部快照的实际占用和共享存储路径。该入口不要求先打开或创建项目；安装状态不代表任一任务已验证连接。任务页的连接状态打开独立详情，显示本任务的验证时间、最近事件和诊断。任务设置保留记录方式、保护仓库、本任务历史清理和移除；重命名移到任务名称旁，复制路径、打开目录移到任务路径旁。

左侧各项目菜单提供“存储管理”，按任务列出检查点数和引用空间。项目引用空间按内容哈希去重；任务之间、项目之间仍可共享对象，因此各项引用空间不能相加当作实际磁盘占用。清理预览另列实际可释放字节，保留其他项目、任务基线、恢复和重做备份、未带回成果所需的快照。

项目清理只处理 `workspaceId` 一致的任务，即使其他项目包含相同源目录也不删除其记录。先预检项目内全部任务，任一记录进行中或存在待恢复操作时整批阻止；执行前重新核对内容指纹，在全局写锁和对象删除锁内一次保存记录变更，再回收无引用对象。中断回收会报告实际释放量和错误，可重新预览重试。清理不改动项目代码、暂存区或提交。

`docs/manual/screenshots/checkpoint-management/` 包含浏览器展示数据下的任务入口、独立连接详情、全局设置、项目存储与清理预览、深浅主题、中英文和窄窗口检查。独立标识的 Tauri 实例使用既有临时 Git 验收数据的副本，实际完成项目历史预览、二次确认和清理；核对另一项目记录、原临时仓库文件及 Git 索引均未改变。本次没有安装或更新用户的全局 Hook，也未重测真实 Codex 桌面事件。

项目侧栏搜索默认收起到“项目”标题旁的放大镜，检查点搜索与仓库筛选收进“检查点记录”标题栏。搜索按需在原标题栏内展开，项目搜索替换标题文字，检查点标题栏固定高度，不新增搜索行；窄窗口展开检查点搜索时临时让出标题位置。有关键词时保持可见；Esc 先清空关键词，再收起输入框并将焦点还给按钮，不关闭检查点中心。仓库筛选使用带选中标识的菜单，启用后图标高亮、悬停显示所选仓库；选择全部仓库即可清除筛选。
