# 舒适布局验收记录

日期：2026-10-03。平台：macOS，原生 Tauri/WKWebView。

## 实现与设置

设置 → 外观 → 界面 → 布局密度，可切换「舒适」和「紧凑」，即时生效并保存。默认舒适，与插件一致；旧设置缺少该字段时也默认舒适。

舒适模式统一使用 8px 卡片圆角、6px 列表内缩和 5px 行圆角，覆盖提交标签栏、三种更改显示模式、辅助标签页、同步底栏、日志侧栏、筛选菜单、详情和代码页外框。仓库标题保留项目颜色，普通选择使用灰色；多选框、数量徽标、分支标签和增删统计保留原有语义颜色。

日志虚拟行仍为连续 28px，外缘增加 4px 空间，仓库色条同步调整位置；切换不重新扫描仓库、不重新加载日志，并保留当前选择和面板尺寸。紧凑模式恢复原有布局。另修复设置下拉菜单在滚动容器底部被裁切的问题，空间不足时向上展开。

## 实际验证

使用独立 QA App 和临时双仓库，同一批真实 Git 提交、分支、标签、stash 与 linked worktree。插件通过独立 Extension Development Host 打开相同仓库，对照其共享密度样式和原生画面；插件源仓库只读。

已检查深色／浅色主题、舒适／紧凑切换、简化视图／VS Code 视图／更改列表、暂存展开、工作树、同步、提交详情，以及搁置／子模块／Subtree 空列表。800×480 窗口检查底部表单、列表滚动和详情显示。原生设置切换后确认 `state.json` 已写入所选密度，重新启动 QA App 后恢复生效。

## 第二轮复查

用户要求再次检查后，按插件共享密度样式、提交主容器、日志比较模式和独立详情页逐项核对，发现第一轮确实遗漏了以下细节，现已修复：

- 详情、变更页和工作树文件行使用 `width: auto` 时，原生按钮按内容收缩。改为容器宽度减去左右各 6px，使悬停、选中和右侧状态对齐；涵盖普通及虚拟详情列表。
- 同步提交展开文件树／平铺文件行缺少密度语义；同步卡片上下分隔线占满整行。接入统一行、卡片和卡片正文规则，选择反馈只覆盖内缩行。
- 子模块有数据时的标题悬停和分隔线未分别处理。接入相同语义，在真实临时子模块中验收。
- 分支／详情侧栏折叠后缺少 6px 卡片间距；主拖拽条原有负边距抵消留白。补齐折叠间距和拖拽条宽度，并对齐侧栏搜索、分组高度、行内边距及吸顶分隔线。
- 已选提交标签悬停时受全局 `!important` 规则影响。复用 `--panel-button-hover` 保留灰色选择背景；同步补齐底部操作外框 6px 圆角、AI 输入边框圆角和比较模式顶部留白。
- 补齐列表及标题背景的短过渡、辅助标签页上下内边距和详情工具栏实际高度。

筛选菜单经原生测量，已有 6px 外框圆角、4px 行圆角及 4px 内缩生效，没有发现原先怀疑的旧样式覆盖。

本轮使用独立 macOS QA App，读取真实临时 Git 仓库，新增真实本地子模块，仅在 QA 开发服务器注入诊断脚本采集 `getBoundingClientRect` 与 `getComputedStyle`；产品源码不包含诊断入口。26 项原生几何／模式还原断言通过，详情和同步行在舒适模式下左右均为 6px、圆角 5px，紧凑模式下均为 0。浅色和深色切换、小窗口滚动及侧栏折叠均实际检查。

本轮最终 `npm run check:frontend` 再次通过：72 个文件、615 项测试。Rust 未修改，沿用上一轮已通过的 157 项测试结果。

## 标签页颜色修正

用户随后反馈提交标签页选中颜色不对。本次按插件原色调整：舒适标签使用 `--vscode-focusBorder` 的 16% 淡底色和 32% 边框，紧凑标签使用主题强调色下划线；选中标签的悬停和键盘焦点继续保持自身选中样式。普通列表仍使用灰色，多选框、徽标和分支标签各自颜色不变。

前述灰色标签悬停截图和 `review/tab-hover-final.json` 仅记录第二轮复查时的状态，不能作为本次标签原色修正的验收依据。

验证：`npm run build` 和 `git diff --check` 通过；使用复制的产品 CSS 在独立原生 WKWebView 样式预览中验证 8 套主题、两种布局，共 16 组颜色样本。见[颜色预览](tab-colors/colors.png)和[计算颜色](tab-colors/computed.json)。这是标签样式验收，不是本轮完整 App 各标签业务流程验收。
