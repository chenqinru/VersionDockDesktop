# VersionDock Desktop 需求说明

你是一名资深 Tauri、Rust、React 和桌面端架构工程师。请参考现有 VersionDock VS Code 插件，开发可独立运行的跨平台桌面应用 VersionDock Desktop。

## 1. 项目边界

现有插件（只读参考源）：`/Volumes/WorkSSD/Project/VersionDock`

桌面端（唯一写入目标）：`/Volumes/WorkSSD/Project/VersionDockDesktop`

必须遵守：

- 所有桌面端代码、资源、配置、测试和文档均写入 VersionDockDesktop；直接在该目录根部创建工程，不要再嵌套同名目录或 `app/desktop` 根目录。
- 未经明确授权，不得修改 VersionDock 或改变其 Git 工作区状态。
- VersionDockDesktop 必须能脱离 VersionDock 独立克隆、构建、测试和发布。
- 禁止通过跨目录 import、绝对路径依赖、npm `file:`、符号链接、Git Submodule 或构建时复制依赖 VersionDock。
- 可以迁移原插件代码和资源，但必须清除 VS Code Runtime 依赖，保留 GPL-3.0-only 许可证及必要版权说明。
- 不使用 iframe 包装插件，不模拟 VS Code Host，不使用 Node.js Sidecar 作为正式运行时。
- 不执行无关重构，不覆盖已有改动，不自动提交或推送。
- 分析和开发命令必须使用各自的工作目录，两个项目的 Git 状态与验证结果分别报告。

## 2. 目标与技术栈

使用 Tauri 2、Rust、React 18、TypeScript、Vite、Zustand、Codicons 和 Shiki，支持 macOS、Windows、Linux。

第一版要求：

- 不安装 VS Code 也能独立运行，发布产物不依赖 Node.js Runtime。
- 迁移真实可用的 Git/SVN 核心工作流。
- UI 与现有 VersionDock 保持一致。
- 使用无边框窗口，支持中英文以及暗黑/浅色模式。
- 不实现任何 AI 功能。

开始编码前先分析源码、Host/Webview 协议、Git/SVN Service、国际化、主题与截图。能从代码或环境确认的信息不要询问用户；审计后若无重大阻塞，直接实施。

## 4. 窗口与 UI

### 无边框窗口

- 使用 Tauri `decorations: false`，不依赖透明窗口。
- 实现自定义标题栏、拖动、双击最大化/还原、最小化、最大化/还原和关闭。
- macOS 使用左侧红黄绿按钮；Windows/Linux 使用平台习惯的右侧按钮。
- 拖动区不得覆盖输入框、按钮和菜单；最大化时正确处理边缘、圆角和安全区域。
- 默认尺寸建议 1440×900，最小尺寸建议 1024×680。
- 持久化窗口位置、尺寸、最大化状态和分栏宽度。
- 禁用浏览器默认右键菜单，使用应用自己的上下文菜单。

### UI 一致性

“保持一致”是验收条件。必须保留：

- 紧凑的信息密度、分区、间距和分隔线
- Commit Panel 文件树与现有标签结构
- Git Log 分支侧栏、提交图谱、列表和详情布局
- 文件状态色、仓库颜色、Codicons 和文件图标
- 按钮、输入框、菜单及 Hover、Selected、Focus、Disabled 状态
- 可拖动分栏
- Diff/Merge Editor 的代码字体、语法高亮和颜色语义

不要改造成大圆角卡片后台、营销页、移动端布局、默认 Material UI 或全新设计系统。新增的标题栏、工作区页和设置页也应沿用 VersionDock 的紧凑视觉语言。

主布局：

```text
┌────────────────── 自定义标题栏 ──────────────────┐
│ Commit Panel │ Branch Sidebar │ Commit Log │ Detail │
└───────────────────────────────────────────────────┘
```

主要分栏均需支持拖动和持久化。

## 5. 主题与国际化

### 主题

支持跟随系统（默认）、浅色、深色，运行时即时切换并持久化；跟随系统时监听系统变化。

标题栏、Commit、Log、Diff、Merge Editor、菜单、弹窗和滚动条必须同步切换，Shiki 使用对应语法主题。浅色模式需验证文字、边框、选中态、状态色和 Diff 色块的对比度。

建立 Theme Adapter，在根节点提供现有 `--vscode-*` 兼容变量，并逐步定义 `--versiondock-*` 语义 Token。不要机械替换全部变量，也不要让桌面端依赖 VS Code Host。

### 国际化

支持跟随系统、简体中文 `zh-CN` 和英文 `en`，非中文系统默认英文；运行时即时切换并持久化。

- 迁移 VersionDock 的 `l10n/bundle.l10n.json` 和 `l10n/bundle.l10n.zh-cn.json`。
- 兼容现有 `t(message, args)` 调用方式。
- 新增可见文案不得散落硬编码。
- 菜单、弹窗、空状态、错误、设置、标题栏和原生文件选择均需翻译。
- 检查中英文长度变化，避免截断、重叠和布局跳动。

## 6. 平台桥接

React 组件不得直接调用 `acquireVsCodeApi()`，也不得散落 Tauri `invoke()`。

在 VersionDockDesktop 定义平台无关接口，例如：

```ts
interface VersionDockBridge {
  send(message: UiToHostMessage): void;
  request<T>(
    message: UiToHostMessage,
    options?: { timeoutMs?: number; signal?: AbortSignal }
  ): Promise<T>;
  subscribe(handler: (message: HostToUiMessage) => void): () => void;
  getState<T>(): T | undefined;
  setState<T>(state: T): void;
}
```

第一版实现 `TauriBridge`，统一封装 invoke、event、requestId、明确响应、结构化错误、超时、取消、进度、订阅清理和本地持久化。组件只能依赖 Bridge，不能直接依赖 Tauri Command/Event 名称。

不要实现无实际用途的 `VsCodeBridge`，也不要修改原插件接入新 Bridge。区分业务消息、VS Code 专属消息、桌面端消息、请求响应和状态事件；Rust 与 TypeScript 数据结构通过集中 Schema 或类型生成保持一致。

## 7. 工作区生命周期

- 首次启动显示工作区选择页，支持选择和拖入文件夹。
- 显示、打开和移除最近工作区，记住上次工作区。
- 支持多仓库和 Git/SVN 混合目录，沿用现有扫描、嵌套归属及去重规则。
- 明确显示未发现仓库、Git 未安装、SVN 未安装等状态。
- 支持在系统文件管理器中显示工作区或文件。
- “Jump to Source”使用可配置外部编辑器；未配置时使用系统默认应用。
- 不把 VS Code 专属能力伪装成桌面能力。

## 9. AI 功能边界

第一版禁止实现或调用 AI Commit Message、AI Commit Composer、AI Code Review、AI Commit Explanation、AI Merge Conflict Resolution，以及任何 Provider、API Key、Prompt 管理或 AI 网络请求。

隐藏全部 AI 按钮、入口和设置，不保留点击无效的控件，也不得破坏周边布局。原插件 AI 代码不得修改；迁移组件含 AI 控件时，通过统一的 Desktop Feature Capability 隐藏，避免散落临时判断。

## 10. Rust Backend

Git/SVN 与本地系统操作由 Rust Backend 执行：

- 使用结构化 `command + args + cwd`，禁止拼接 Shell 字符串处理用户输入。
- 校验操作路径位于当前工作区范围内。
- 正确处理空格、中文和特殊字符路径。
- 支持有限并发、超时、取消、进度、stdout/stderr 分离、Exit Code 和输出上限。
- 不记录密码、Token、Authorization Header 或敏感环境变量。
- rollback、delete、drop stash、reset、force delete branch 等破坏性操作必须确认。
- 状态刷新应防抖、去重，避免旧请求覆盖新状态。
- 文件监听不能形成全仓库刷新循环。
- 窗口关闭时终止订阅、后台任务和子进程。

统一错误结构至少包含：

```ts
interface DesktopError {
  code: string;
  message: string;
  command?: string;
  exitCode?: number;
  stderr?: string;
  recoverable: boolean;
}
```

## 11. 状态与性能

持久化最近/上次工作区、语言、主题、窗口状态、面板宽度与折叠状态、Commit Panel 标签、Git Log 过滤条件、文件视图模式和工作区偏好。内部状态写入标准应用数据目录，不污染用户仓库。

性能要求：

- 先显示窗口骨架，状态、分支和日志分阶段加载。
- 保留 Commit Log 分页和虚拟列表。
- 大文件 Diff 设置上限并明确提示。
- React Render 中不得执行 Git/SVN 或高成本计算。
- 文件监听使用增量或防抖刷新。
- 多仓库任务限制并发，主界面不得明显卡顿。

3. **平台桥接**：完成 VersionDockBridge、TauriBridge、数据契约、错误、请求响应、事件、进度、取消、超时和持久化。

## 14. 完成定义

只有全部满足以下条件才能宣布第一版完成：
